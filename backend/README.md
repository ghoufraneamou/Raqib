# Raqib – Backend

Backend of **Raqib**, the AI-driven regulatory validation system for AMMPS (Moroccan Agency for Medicines and Health Products). It exposes the full validation pipeline as a REST API.

```
PDF / Image
   └─► OCR (EasyOCR)
         └─► LayoutLMv3 embeddings (optional)
               └─► YOLOv8 (signature / stamp / official header)
                     └─► Document classification + rule-based validation
                           └─► Cross-document checks
                                 └─► Compliance score, risk level and report
```

## 1. Features

- **Multi-file upload** of PDFs and images in one request.
- **Multilingual OCR** (Arabic, French, English) with EasyOCR; digital PDFs use PyMuPDF text extraction.
- **LayoutLMv3** embeddings (can be disabled for speed).
- **YOLOv8** detection of `signature`, `stamp` and `official_header`.
- **Explainable rule-based validation** per document type (passed and failed criteria).
- **Cross-document consistency checks** (ICE, RC, company name, product name, dates).
- **Compliance score and risk level** with a structured report.
- Works without YOLO weights: falls back on text-based hints.

## 5. Run the Server

From the project root:

```bash
uvicorn backend.app:app --host 0.0.0.0 --port 8000
```

Optional, for a faster run without LayoutLMv3:

```bash
export AMMPS_DISABLE_LAYOUT=1        # Windows PowerShell: $env:AMMPS_DISABLE_LAYOUT = "1"
```

- Health check: `GET http://localhost:8000/health`
- Interactive docs: `http://localhost:8000/docs`

## 6. API Usage

### `POST /validate`

| Item | Value |
|------|-------|
| URL | `http://localhost:8000/validate` |
| Body | `multipart/form-data` |
| Form key | `files` (repeat for each file) |
| Formats | PDF, JPG, JPEG, PNG |

```bash
curl -X POST "http://localhost:8000/validate" \
  -F "files=@01_LETTRE_DEMANDE_realistic_scanned.pdf" \
  -F "files=@some_image.jpg"
```

```python
import requests

files = [
    ("files", open("01_LETTRE_DEMANDE_realistic_scanned.pdf", "rb")),
    ("files", open("some_image.jpg", "rb")),
]
print(requests.post("http://localhost:8000/validate", files=files).json())
```

In the full platform, validation runs asynchronously: `/validate` launches a Celery task and returns a `task_id`, and the frontend polls `/status/{task_id}`. Other platform endpoints include `/download-report`, `/dossiers`, `/dossiers/{dossier_id}`, `/appointments/confirm`, `/ask-ai` and the authentication routes. See the root README for the full table.

## 7. Pipeline Details

1. **OCR and text extraction**: EasyOCR (Arabic, French, English). Digital PDFs use PyMuPDF; scanned PDFs are rendered at 200 DPI. Text is normalized (lowercase, whitespace, diacritics).
2. **LayoutLMv3**: `microsoft/layoutlmv3-base` with OCR disabled (EasyOCR supplies words and boxes, normalized to a 0 to 1000 scale). Produces contextual embeddings for future learning-based validation.
3. **YOLOv8 detection**: finds signatures, stamps and official headers. Results are stored per class with page number, confidence and coordinates.
4. **Classification and validation**: keyword pattern matching assigns a document type; a type-specific validator returns `passed_criteria` and `failed_criteria`.
5. **Cross-document consistency**: compares ICE, RC, company name, product name and dates across documents.

**Example (Lettre de demande)**

| Rule | Criterion | Method |
|------|-----------|--------|
| R-LD-01 | Signature present | YOLOv8 |
| R-LD-02 | Official stamp present | YOLOv8 |
| R-LD-03 | Date present (DD/MM/YYYY) | OCR + regex |
| R-LD-04 | Product name stated | OCR keyword matching |
| R-LD-05 | 15-digit ICE present | OCR + regex |
| R-LD-06 | Request type declared | OCR keyword matching |

R-LD-01 to R-LD-04 are mandatory; R-LD-05 and R-LD-06 contribute to scoring and consistency.

## 8. Scoring and Risk Levels

The score is the percentage of validation criteria that pass across the dossier. Failed criteria, missing mandatory documents and inconsistencies lower it.

| Risk | Score |
|------|-------|
| LOW | 85 or more |
| MEDIUM | 60 to 84 |
| HIGH | below 60 |

The score supports decisions; it never replaces human review.

## 9. Configuration (Environment Variables)

### Pipeline

| Variable | Default | Description |
|----------|---------|-------------|
| `AMMPS_YOLO_WEIGHTS` | `backend/weights/best.pt` | Path to YOLO weights |
| `AMMPS_YOLO_CONF` | `0.25` | YOLO confidence threshold |
| `AMMPS_PDF_DPI` | `200` | DPI for PDF to image rendering |
| `AMMPS_DISABLE_LAYOUT` | not set | `1` disables LayoutLMv3 |

### Weak scans (signature)

| Variable | Default | Description |
|----------|---------|-------------|
| `AMMPS_YOLO_CONF_SIGNATURE` | ~`0.14` | Validation threshold for signatures |
| `AMMPS_YOLO_PREDICT_CONF` | ~`0.08` | Minimum confidence at inference |
| `AMMPS_YOLO_ENHANCE` | enabled | `0` disables CLAHE pre-processing |

### Platform

| Variable | Description |
|----------|-------------|
| `AMMPS_JWT_SECRET` | Secret key used to sign JWT tokens (HS256) |

Keep all secrets (JWT key, database, SMTP, Groq API key) in environment variables, never in the code or in the repository.

## 10. Training the YOLO Model

On **Apple Silicon**, MPS training can crash, so the script uses the **CPU** by default.

```bash
cd backend
source .venv/bin/activate
pip install -r requirements.txt
python train_yolo.py --epochs 35 --batch 12 --device cpu
```

The best weights are copied automatically to `backend/weights/best.pt`, and `backend/dataset_yolo.yaml` is generated with absolute dataset paths.

The original model was trained on Google Colab (Tesla T4 GPU). The dataset has 3,667 annotated page images with two classes (signature, stamp), resized to 640 x 640.

---

## 11. Model Performance

| Metric | Value |
|--------|-------|
| Precision | 0.92 |
| Recall | 0.90 |
| mAP@0.5 | 0.93 |
| mAP@0.5:0.95 | 0.66 |

Stamps are detected more reliably than signatures. Signatures can be missed when faint, stylized or partly hidden.

---

## 12. Notes

- YOLO gives the visual evidence for signature, stamp and header criteria; all other criteria are explainable rules on extracted text.
- Without YOLO weights the pipeline still runs using text-based hints.
- Disabling LayoutLMv3 speeds up processing.

## 13. Troubleshooting

| Problem | Solution |
|---------|----------|
| `ModuleNotFoundError: backend` | Run `uvicorn backend.app:app` from the project root. |
| Slow first request | Models load on first use; later requests are faster. |
| Processing too slow | Set `AMMPS_DISABLE_LAYOUT=1` or lower `AMMPS_PDF_DPI`. |
| Signature not detected on a poor scan | Lower `AMMPS_YOLO_CONF_SIGNATURE` or `AMMPS_YOLO_PREDICT_CONF`; keep CLAHE enabled. |
| Training crashes on Apple Silicon | Use `--device cpu`. |
| Empty YOLO results | Check `backend/weights/best.pt` or `AMMPS_YOLO_WEIGHTS`. |
| Port 8000 in use | Use another port, e.g. `--port 8001`. |
| CORS error from the frontend | Allow the frontend origin (Vite uses ports 5173 and 5174). |
